Secure Web Architecture

This page shows how I would securely structure my portfolio website and Jovens AI as the project grows from a static site into a full web application.

Architecture

Proposed Secure Architecture

The current portfolio is mostly a static HTML/CSS/JavaScript site. The design below shows how I would securely add a backend, database, accounts, and AI features.

👤UserVisitor / Student
→HTTPS
🖥️FrontendHTML / CSS / JavaScript

🤖External AI/SearchBackend Only • No Keys in Browser
Required Components

Architecture Components

Each component has a specific job and a security control built around it.

🖥️Frontend

The pages visitors interact with. HTML, CSS, and JavaScript display my portfolio and Jovens AI interface. User input is treated as untrusted.

🌐Web Server

Netlify can host the site and deliver pages over HTTPS. HTTPS protects information while it travels between the visitor and the site.

⚙️Application Layer

Serverless functions or a backend API would handle sensitive logic, AI requests, validation, and database access instead of putting secrets in browser code.

🗄️Database

A future database would store only information the application actually needs. The database would not be directly accessible from the browser.

🔑Authentication

If accounts are added, users would sign in through a trusted authentication provider with secure password handling and optional MFA.

🛂Authorization

After login, the server would check what each user is allowed to do. Normal visitors would never receive administrator permissions.

🔒Encryption

HTTPS/TLS protects data in transit. Sensitive database information and secrets should also be encrypted or securely stored at rest.

🍪Session Management

Sessions would use secure, HttpOnly, SameSite cookies with expiration. Sessions would be invalidated when users sign out.

✅Input Validation

Text, voice-transcribed input, commands, and API parameters should be checked before processing. Output should be escaped to reduce XSS risk.

Security Flow

How Security Is Built Into the Design

User Request→HTTPS→Input Validation→Authentication→Authorization→Application Logic→Database / AI Service
Security Controls

Important Protections

✓ HTTPS for all traffic
✓ Validate all user input
✓ Escape displayed user content
✓ Keep API keys on the server
✓ Authentication for private features
✓ Server-side authorization checks
✓ Secure session cookies
✓ Rate limits for Jovens AI/API requests
✓ Database access only through backend
✓ Least-privilege permissions
✓ MFA for admin/hosting accounts
✓ Backups and Git version control
Overall Design

Simple Security Summary

The main idea is to keep the public website simple while moving sensitive work to a protected backend. The browser should never contain private API keys or directly access a database. HTTPS, input validation, authentication, authorization, secure sessions, and server-side controls would protect the application as more features are added.
