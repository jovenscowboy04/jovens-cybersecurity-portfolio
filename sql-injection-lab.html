SQL Injection Security Lab

A controlled educational comparison showing how unsafe SQL construction can be affected by user input and how secure coding practices reduce the risk.

Required Concepts

Security Controls Used in This Lab

The lab focuses on the four areas required by the assignment.

✅

Input Validation

Check format, length, and allowed characters before input reaches database logic.

🔗

Parameterized Queries

Keep SQL commands separate from user-supplied values by binding data as parameters.

🧩

Prepared Statements

Prepare the SQL structure first, then safely supply values without rebuilding the command string.

🗄️

Secure Database Access

Use a protected backend, least-privilege database accounts, encrypted connections, and no credentials in browser code.

Secure Programming
Prepared Statement Example

        
A secure server-side implementation uses a placeholder instead of concatenating the username into the SQL string:

        
// Server-side example
const sql = "SELECT id, username, role FROM users WHERE username = ?";
const [rows] = await db.execute(sql, [username]);

        
Why this is safer: the database receives the SQL command and the username as separate values. The username is treated as data instead of being interpreted as part of the SQL command.

Defense in Depth

        

          
✓ Validate expected input format
✓ Use parameterized queries
✓ Use prepared statements
✓ Keep database credentials on the server
✓ Apply least-privilege permissions
✓ Use encrypted database connections
✓ Avoid showing detailed database errors to users
✓ Log suspicious input safely
