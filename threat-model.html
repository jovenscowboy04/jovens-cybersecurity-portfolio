Website Threat Model

This page models security threats to my portfolio website and Jovens AI using a structured STRIDE approach. It identifies the architecture, important assets, trust boundaries, likely attack paths, risk levels, and practical mitigations.

SYSTEM

What I Am Protecting

My site is a public HTML/CSS/JavaScript portfolio with four content pages plus Jovens AI. Jovens AI accepts text and voice input, reads from a local knowledge base, changes themes, navigates the site, and can be prepared for future AI/search APIs.

GOAL

Security Objective

Keep the site trustworthy, available, and safe for visitors while preventing malicious input, unauthorized changes, data exposure, misuse of future API credentials, and abuse of chatbot features.

Assets

Important Assets

These are the parts of the system that have value and should be protected.

📄Website Files

HTML, CSS, JavaScript, images, and portfolio content.

🧠Jovens AI Knowledge

Structured information used to answer portfolio questions.

🎙️User Input

Typed questions, voice input, and chatbot commands.

🔐Future API Secrets

AI/search credentials must never be exposed in frontend code.

💾Browser Preferences

Theme, voice, and chat preferences stored locally.

👤Personal Information

Public portfolio details should exclude sensitive PII.

STRIDE

Structured Threat Analysis

STRIDE provides a consistent way to identify threats across the website.

S

Spoofing

Threat: A fake service or attacker pretends to be a trusted user, server, or AI provider.

Mitigation: HTTPS, trusted services, authentication for privileged features, and verified backend connections.

T

Tampering

Threat: An attacker changes website files, Jovens AI responses, or stored settings.

Mitigation: Secure hosting, MFA, restricted permissions, Git/version control, backups, and input validation.

R

Repudiation

Threat: A malicious user performs an action and later denies it.

Mitigation: If a backend is added, log important security-relevant events without collecting unnecessary personal data.

I

Information Disclosure

Threat: Sensitive information, API keys, or private user data becomes visible.

Mitigation: No secrets in frontend code, minimum necessary personal information, HTTPS, and secure server-side storage.

D

Denial of Service

Threat: Excessive chatbot/API requests make services slow or unavailable.

Mitigation: Rate limits, message-size limits, quotas, caching, and hosting protections.

E

Elevation of Privilege

Threat: A normal visitor reaches administrative or backend actions they should not control.

Mitigation: Server-side authorization, least privilege, allow-listed commands, and no arbitrary code execution.

Risk Register

Website-Specific Threats

These threats are the most relevant to my current site and its planned AI features.

ThreatExampleRiskMitigation
Cross-Site Scripting (XSS)Malicious HTML/JavaScript submitted through Jovens AI input.HighUse textContent, sanitize input, escape output, and deploy a Content Security Policy.
API Key ExposureAn AI/search API key is placed inside client-side JavaScript.HighStore secrets in environment variables and route requests through a backend/serverless endpoint.
Prompt InjectionA visitor tells an AI-enabled Jovens AI to ignore instructions or reveal secrets.HighKeep secrets outside the model context, restrict tools/actions, validate commands, and enforce server-side controls.
Unauthorized ModificationAn attacker changes portfolio files or inserts malicious code.HighStrong passwords, MFA, secure hosting permissions, backups, and version control.
Information LeakageToo much personal information or chatbot data is exposed.MediumPublish only professional information, minimize logs, avoid sensitive PII, and use HTTPS.
Voice PrivacyThe microphone appears active when the visitor did not intend to record.MediumRequire user activation, show listening status, provide a stop control, and do not secretly store audio.
Malicious CommandsA user tries to make Jovens AI execute unsupported navigation or arbitrary JavaScript.MediumUse an allow-list of safe actions and never evaluate user-supplied JavaScript.
Browser Storage ManipulationA visitor manually changes localStorage values.LowOnly store non-sensitive preferences and validate values before applying them.

Primary Entry Points

Security Controls

Recommended Protections

✓ HTTPS everywhere
✓ Input validation & output escaping
✓ Content Security Policy
✓ No secrets in frontend code
✓ Backend proxy for AI/search APIs
✓ Rate limiting & message limits
✓ MFA for hosting/admin accounts
✓ Least-privilege permissions
✓ Safe command allow-list
✓ Backups & Git version control
✓ Visible microphone status
✓ Minimal collection of personal data
Conclusion

Overall Assessment

Overall, my website is fairly low risk because it is mainly a public portfolio. The biggest security concerns come from Jovens AI, user input, voice features, and any future AI connections. I can reduce these risks by validating input, protecting API keys, using HTTPS, and limiting what Jovens AI is allowed to do.
